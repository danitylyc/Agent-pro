# Workflow Agent Lab 架构说明

## 业务问题

退款流程同时具有长程依赖、工具失败和高风险动作。直接让模型连续调用工具，会把早期错误累积到最终提交；而固定规则又无法利用失败轨迹改进动作选择。

## 系统边界

```text
任务生成器
   ↓
RefundWorkflowEnv  ← 故障注入 / 风险规则 / 自动 oracle
   ↓
Agent policy       ← naive / safe_recovery / offline Q
   ↓
动作适配器         ← Python env / HTTP API / DOM Selenium
   ↓
轨迹记录与评测     ← 成功率 / 危险提交 / 恢复率 / 步数
```

## 关键设计

1. 每个关键状态都可验证，避免只依赖模型自报成功。
2. 高金额或过期订单必须转人工，不允许直接提交。
3. 工具错误只允许有限重试，避免无限循环。
4. 轨迹同时记录行为策略、状态、动作、奖励和终止信息，可用于离线训练。
5. 评测与交互层解耦，因此可以从本地环境扩展到 HTTP、浏览器或真实工具。

## 当前限制

- 业务页面和订单数据是本地模拟，不包含真实客户数据。
- 当前离线 Q 是可审计的 tabular 版本，后续可以替换为神经 action scorer。
- Selenium 适配器已实现，但本机缺少匹配的 Edge WebDriver；HTTP 端到端评测是当前已验证路径。
